## Explore an illustrative example

An automated service reports `FAILED`; a separate **fictional** observation says `SUCCEEDED`. The two values disagree. The demo presents that as **CONTRADICTED**. When no observation is provided, it returns **UNSUPPORTED** rather than silently trusting a success message.

[Open the interactive `demo.html` file](demo.html) in a browser and explore four fictional cases. No dependencies, server, live APIs, or client data are required. This is a **new, simplified, self-contained public demonstration**, not a release of our private verification engines.

## Why it matters

- Distinguish **what a system claims** from **what the available evidence can support**.
- Keep missing evidence from being misrepresented as confirmed execution.
- Define testable failure, retry, recovery, and incident review paths.
- Make authority, evidence custody, and operational acceptance explicit.

## Scope and trust boundaries

This public repository is a **commercial showcase and synthetic demonstration**, not a customer case study, a live PostgreSQL test, an independently audited security control, or a production deployment. The interactive classifications are deterministic comparisons of fictional example values. They do not authenticate the observations, establish causality, or prove exactly-once external effects.

Actual client projects require a separately scoped engagement, suitable permissions, authoritative data sources, appropriate independent roles, and environment-specific acceptance.
